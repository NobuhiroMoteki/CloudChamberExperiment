# 雲チェンバー 計測制御プログラム 操作マニュアル

減圧式の雲チェンバーで、レーザー透過率と気圧・温度を測り、バルブを自動で開閉しながら、
水蒸気混合比 qw と粒子数濃度 N を 60 秒ごとに推定・表示・記録するプログラムの使い方です。
LabVIEW 版（`CloudChamberOperation_AutoValve.vi`）を Python に移植したものです。

---

## 1. 構成

| 項目 | 内容 |
|---|---|
| DAQ | NI USB-6210（推奨）または USB-6008 / USB-6009 |
| センサー | フォトダイオード（レーザー透過光）、気圧計 Setra 276、サーミスタ（NTC、B = 3435 K） |
| 参照測定器 | 鏡面式露点計 東京光電子工業 DPH-203B（相対湿度 0〜1 V、露点温度 約 10 mV/℃）、凝縮粒子計数器 TSI 3022A（RS-232、USB-シリアル変換で COM3。9.4 節） |
| バルブ | 電動ボールバルブ 2 個（V1：吸気、V2：真空ポンプ側）。トランジスタとリレーで駆動 |
| PC | Windows、NI-DAQmx ドライバ、Python 環境 `cloudchamber`（Miniforge） |

主なファイル（`Python` フォルダ内）:

| ファイル | 役割 |
|---|---|
| `run_gui.bat` | GUI の起動用。ダブルクリックで起動する |
| `check_daq.py` | センサーの値を読むだけの点検用スクリプト（バルブには触れない） |
| `cpc_logger.py` | GUI を使わずに CPC だけを記録するスクリプト（9.4 節） |
| `run_sbi_shape3.py` | Tr 形状の SBI（版3）の学習と、露点計・CPC との比較（6.2 節） |
| `cloudchamber/` | プログラム本体（制御・解析・推定・画面） |
| `MANUAL.md` | このマニュアル |

## 2. 準備（初回のみ）

### 2.1 Python 環境

Miniforge を `%USERPROFILE%\miniforge3` にインストールし、次のコマンドで環境 `cloudchamber` を作ります
（このPCでは作成済みです）。

```
conda create -n cloudchamber -c conda-forge python=3.12 numpy scipy pandas matplotlib numba pyqtgraph pyqt pytorch
conda activate cloudchamber
pip install sbi nidaqmx pyserial
```

> **重要**: Python は必ず環境を有効化してから実行してください（`run_gui.bat`、
> `conda activate cloudchamber` の後、または `conda run -n cloudchamber ...`）。
> `envs\cloudchamber\python.exe` を直接実行すると、数値計算ライブラリ（MKL）が読み込めず、
> エラーメッセージなしで異常終了することがあります。

### 2.2 NI-DAQmx

NI-DAQmx（25.5 以降）をインストールします。DAQ を USB で接続すると NI MAX にデバイスが現れ、
`Dev1`、`Dev2` などの名前が付きます。**この名前を GUI の「デバイス」欄に入力します。**

> 同じ DAQ を LabVIEW と同時に使うことはできません。Python 版を使うときは LabVIEW の VI を止めてください。

## 3. 配線

### 3.1 アナログ入力（すべての機種で共通、シングルエンド RSE）

| チャンネル | 信号 | 電圧の目安 | USB-6210 のレンジ | USB-6008/6009 のレンジ |
|---|---|---|---|---|
| ai0 | フォトダイオードの電流-電圧変換回路の出力 | 最大 約 8 V | ±10 V | ±10 V |
| ai1 | 気圧計 Setra 276 の出力 | 0.1〜5.1 V（大気圧で約 3.8 V） | ±5 V | ±10 V |
| ai2 | サーミスタ分圧回路の出力 | 約 1〜2.5 V | ±5 V | ±10 V |
| ai3 | 鏡面式露点計の相対湿度出力 | 0〜1 V（0〜100 %） | ±1 V | ±10 V |
| ai4 | 鏡面式露点計の露点温度出力（電圧、約 10 mV/℃） | 約 ±1 V（−100〜+100 ℃） | ±1 V | ±10 V |

センサー側の GND は DAQ の AI GND に接続します。

**露点温度出力の換算（校正式）**

露点計（DPH-203B）のマニュアルには「4〜20 mA の電流出力」と書かれていますが、誤りで、実際は電圧出力です。
5 点の校正データ（露点 −10.3〜30.2 ℃、周囲温度 20〜22 ℃）に直線を当てはめた式を使います
（残差の二乗平均 0.06 ℃）。

> Td [℃] = 0.100574 × V [mV] − 0.1018

校正し直した場合は、`cloudchamber/conversions.py` の `TD_SLOPE` と `TD_OFFSET` を変更します。

> **結露に注意**: 外気の露点温度が室温より高いとき（夏の東京など）は、配管やチャンバーの壁で結露して
> 試料空気の水蒸気が減ります。取り込み口から各測定器までの配管とチャンバーを、外気の露点温度より
> 高い温度に保ってください。

換算式（LabVIEW 版と同じ）:

- 気圧: p [hPa] = −27.6 + 276 × V
- 温度: 1/T = 1/298.15 − (1/3435)·ln[(5.07/V − 1)·R0/29.5 kΩ − R0/R_in]、R0 = 9.2 kΩ（公称 10 kΩ を露点計の温度計に合わせて 1 点校正、`calib_thermistor.py`）、R_in = ADC 入力抵抗（USB-6008: 1.75 MΩ、USB-6210: ∞）

### 3.2 デジタル出力（バルブ）

| 機種 | V1（吸気） | V2（真空ポンプ側） |
|---|---|---|
| USB-6210 | `port1/line0`（PFI4） | `port1/line1`（PFI5） |
| USB-6008 / 6009 | `port0/line0` | `port0/line1` |

- 出力が **True（High）でバルブが開** きます。
- 端子の物理的な位置は、各 DAQ のピン配置表で確認してください。
- 駆動回路の抵抗 R1（22 kΩ）は、出力 5 V を前提に選んでいます。

### 3.3 安全な状態

プログラムの開始時・停止時・エラー時には、バルブを **V1 開・V2 閉**（チャンバーは大気に開放、
ポンプからは遮断）にします。

## 5. 初めて使うときの点検手順

新しく配線したときや、DAQ を替えたときは、次の順に確認してください。

### 手順 1：センサーの値を読む（バルブは動かない）

コマンドプロンプトで:

```
cd %USERPROFILE%\CloudChamberExperiment\Python
%USERPROFILE%\miniforge3\Scripts\conda.exe run -n cloudchamber python check_daq.py Dev2 USB-6210 3
```

（デバイス名と機種は実際のものに合わせます。USB-6008 なら `Dev1 USB-6008/6009`）

確認すること:

- 気圧が室内の気圧（約 1000 hPa）になっている
- 温度が室温になっている
- PD 電圧が、レーザーが当たっているときに数 V（最大 約 8 V）、遮ると 0 V 付近になる
- 露点計の相対湿度と露点温度が、露点計本体の表示と一致する

> 3 つのチャンネルがほぼ同じ電圧（約 1.4〜1.7 V）を示す場合は、入力に何もつながっていません。

### 手順 2：バルブを 1 つずつ動かす（ポンプは止めておく）

1. 真空ポンプを止めておく。
2. GUI で「手動運転 開始」を押す（V1 開・V2 閉になる）。
3. V1 ボタンを押して閉 → 開、V2 ボタンを押して開 → 閉、と 1 つずつ操作し、
   **正しいバルブが、正しい向きに動くか** を目と音で確かめる。
4. 「停止」を押す。

### 手順 3：自動運転を数サイクル行う

ポンプを動かし、「自動運転 開始」を押して、2〜3 サイクル（2〜3 分）様子を見ます。

- 段階が 空気置換 → 気圧緩和 → 密閉 → 減圧 → 開放 → 待機 と切り替わる
- 減圧中に気圧が下がり、I/I0 が下がって雲が出る
- 減圧が終わると、右側の P(t)・Tr(t) のグラフと推定値が更新される
- データフォルダに `cloud_data_YYYYMMDD.csv` と `raw_YYYYMMDD` フォルダができる

## 6. 自動運転

### 6.1 運転サイクル（既定は各 10 秒、合計 60 秒）

| 段階 | V1 | V2 | 内容 |
|---|---|---|---|
| 1. 空気置換 | 開 | 開 | 新しい試料空気を取り込む |
| 2. 気圧緩和 | 開 | 閉 | チャンバー内を外の気圧になじませる |
| 3. 密閉 | 閉 | 閉 | 試料空気を閉じ込める。終わりに I0・T_ini・p_ini を確定 |
| 4. 減圧 | 閉 | 開 | 減圧して雲を作り、気圧と透過率を 10 ms ごとに記録 |
| 5. 開放 | 開 | 閉 | 大気圧に戻す（この間に解析・推定を行う） |
| 6. 待機 | 開 | 閉 | サイクルの長さの調整 |

### 6.2 測定と解析の内容

- アナログ入力は DAQ のハードウェアクロックで **100 Hz（10 ms ごと）** に取得します。
- **密閉の終わり（減圧開始の直前）** に次の値を確定します。
  - I0：フォトダイオード出力の直近 10 秒の中央値（起動から 10 秒未満なら確定しない）
  - T_ini、p_ini：温度と気圧の直近 1 秒の中央値
- **減圧の後** に次の解析を行います。
  - 透過率 Tr = PD 電圧 / I0
  - 気圧の変化 p(t) = (p_ini − p_offset)·exp(−t/τ_vac) + p_offset を、
    気圧が実際に下がり始めた時刻 t0 から 3 秒間でフィットする（t0 もフィットで求める）
  - Tr が最初にしきい値（0.985）以下になったサンプルを雲の発生時刻 t_c とし、
    そのときの気圧を p_c とする
  - ζ_moist = 1 − p_c/p_ini
  - t_s = Tr が 1 から下がり始めた時刻（t_c より前で、Tr が「減圧前の Tr の中央値 − max(5σ, 0.001)」以上だった最後のサンプル。σ は減圧前の Tr のばらつき）
  - ζ_turbid = t_s から 0.3 秒間の Tr の直線フィットの傾き（符号を反転、単位 s⁻¹）。t_c はしきい値による雲発生の判定と p_c に使う
  - 推定器で qw と N を求める

**推定器（Tr 形状の SBI）**: 学習済みの版のうち最も新しいものを自動で使います。
`models\npe_shape3_*.pt`（版3、CSV の estimator 列は `ShapeSBIEstimator3`）、
`models\npe_shape2_*.pt`（版2、`ShapeSBIEstimator2`）、`models\npe_shape_*.pt`（版1、`ShapeSBIEstimator`）の順で探し、
どれも無ければ線形回帰を使います。

- 気圧は、バルブが開く間のランプ（t_open）と二重指数関数でフィットする:
  p(t) = p_offset + (p_ini − p_offset)·[f·exp(−G/τ₁) + (1−f)·exp(−G/τ₂)]、G はランプを考慮した経過時間。
  気圧が下がり始めた時刻 t0 もフィットで求める
- t − t0 を時間軸として、Tr が下がり始めた時刻 t_s（減圧前の Tr の中央値 − max(5σ, 0.001) を下回る時刻、サンプル間は直線補間）と、
  t_s − 0.10 s から、版2では t_s + 0.90 s（2つ目のこぶ、雲粒半径 約 3 µm まで）、版1では t_s + 0.35 s（最初のこぶ、約 2 µm まで）の
  Tr の形（0.01 s ごと）を使う
- 版2では、凝縮成長による雲粒の大きさのばらつきの縮小と、実効光路長（0.14〜0.20 m）の不確かさもモデルに入れている。
  壁からの熱伝導は、版1・版2では局外パラメータとして周辺化している
- **版3**（`cloudchamber\sbi_shape3.py`）は版2と同じ x を使い、モデルを次のように変えている
  - 湿潤空気の熱力学を修正（潜熱の項を −l_v dq_v/dt に、水蒸気圧を e = q_v p/(ε+q_v) に）。
    D_v、k_a、水の表面張力は気温・気圧に依存させる（`cloudchamber\activation.py`）
  - 壁からの加熱は入れない（光が通るフラスコの中心部は断熱的に冷える）
  - **気圧センサーの補正**: 実際の気圧低下 = (0.90〜0.94) × 測った気圧低下、センサーの読みはフラスコ内の気圧より
    0.25〜0.31 s 遅れる。記録した 12 サイクルで qw を露点計の値に固定して求め、別の 12 サイクルで検証した
    （qw は露点計の ±6% 以内）
  - 実効光路長は 0.18 m に固定
  - 学習に使っていないシミュレーションでの誤差（二乗平均平方根）は qw 0.27 g/kg、log10 N 0.027。
    記録した 1755 サイクルでは qw ÷ 露点計 の中央値 1.036（77% が ±10% 以内）。
    N は CPC の約 1.5〜1.7 倍で、原因はまだわかっていない
- これに T_ini、p_ini、気圧フィットのパラメータを加えて、学習済みの事後分布から qw と N の中央値と 90% 信用区間を求める
- 学習は `run_sbi_shape3.py`（版3）、`run_sbi_shape2.py`（版2）、`run_sbi_shape.py`（版1）で行う
  （シミュレーション 3 万回、約 10〜15 分）。モデルを変えたときは学習し直す

ζ_moist・ζ_turbid は、比較のために引き続き計算して CSV に記録しますが、推定には使いません。

**長時間の連続運転**: あるサイクルの解析・推定・保存で例外が起きても、運転は止まりません。
そのサイクルは NaN とフラグ付きで保存され、内容はデータフォルダの `warnings_YYYYMMDD.log` に書かれます。
DAQ の読み取りエラー（USB の抜けなど）のときは、バルブを安全な状態にして運転を止めます。

---

## 7. 手動運転

「手動運転 開始」を押すと、段階の自動切り替えを行わず、V1・V2 のボタンでバルブを操作できます。

- 開始時はバルブが安全な状態（V1 開・V2 閉）になります。
- PD 電圧・気圧・温度・I/I0 とグラフは更新され続けます。I0 は直近 1〜10 秒の中央値を使います。
- **データの記録と推定は行いません。**
- 「停止」を押すと、バルブを安全な状態に戻して終了します。

---

## 8. シミュレーションモード

「モード」を「シミュレーション」にすると、DAQ を使わずに、物理モデルで作った信号で動作します。
バルブも DAQ も動かないので、画面の操作の練習や、プログラムの動作確認に使えます。
qw と N は時間とともにゆっくり変わるように設定されています。

## 9. 出力ファイル

保存先は「データフォルダ」です。手動運転・停止中は保存しません。

### 9.1 サイクルごとの記録 `cloud_data_YYYYMMDD.csv`

1 日 1 ファイル、1 サイクル 1 行。カンマ区切り、1 行目は見出し、UTF-8。

| 列 | 内容 | 単位 |
|---|---|---|
| Time_stamp | 減圧の段階を始めた時刻（UNIX 時刻、1970-01-01 UTC からの秒数） | s |
| datetime | 同じ時刻の現地時刻（ISO 8601、例 `2026-10-28T14:16:39+09:00`） | — |
| T_ini | 減圧直前 1 秒の温度の中央値 | K |
| p_ini | 減圧直前 1 秒の気圧の中央値 | hPa |
| p_offset | p(t) フィットの到達圧 | hPa |
| tau_vac | p(t) フィットの時定数 | s |
| p_c | 雲の発生時の気圧 | hPa |
| zeta_moist | 1 − p_c/p_ini | — |
| zeta_turbid | t_s（Tr が下がり始めた時刻）から 0.3 秒の Tr の傾き（符号反転）。2026-10-29 午後以前のデータは t_c 起点 | s⁻¹ |
| t0 | 減圧段階の開始から、気圧が下がり始めるまでの時間 | s |
| I0 | 基準光強度 | V |
| qw_gkg, qw_lo, qw_hi | 水蒸気混合比の推定値と信用区間 | g/kg |
| log10nd, log10nd_lo, log10nd_hi | 粒子数濃度の推定値と 90% 信用区間（常用対数） | log10(個/kg) |
| ref_RH | 露点計の相対湿度（密閉段階の最後 10 秒の中央値） | 0〜1 |
| qw_ref_gkg | ref_RH から求めた qw（T_ini に対する相対湿度とみなす） | g/kg |
| ref_Td | 露点計の露点温度（密閉段階の最後 10 秒の中央値） | ℃ |
| qw_ref_td_gkg | ref_Td から求めた qw（WMO の Magnus 式、p_ini を使用）。**参照値としてはこちらを推奨** | g/kg |
| Td_est, Td_est_lo, Td_est_hi | 推定した qw（と 90% 信用区間）に対応する露点（WMO の Magnus 式、p_ini で換算） | ℃ |
| nd_cm3, nd_cm3_lo, nd_cm3_hi | エアロゾル数濃度の推定値と 90% 信用区間（密閉時の状態 p_ini, T_ini の乾燥空気密度で個/kg から換算） | 個/cm³ |
| t_s | ζ_turbid 用の Tr の下がり始め（t0 から） | s |
| t0_ramp2, p_offset2, tau_vac1, frac1, tau_vac2, t_open | ランプ＋二重指数関数の気圧フィット（t0_ramp2 は減圧段階の開始から） | s, hPa, s, —, s, s |
| p_rms | そのフィットの残差の RMS | hPa |
| t_s_shape | Tr 形状の推定に使った下がり始め（t0_ramp2 から） | s |
| cpc_cm3 | CPC の値。減圧の終わりまでの 1 サイクル（60 秒）の 1 秒値（カウント数 ÷ 流量）の中央値。CPC が無いときは NaN（9.4 節）。2026-10-31 の変更より前は V1 閉の間（密閉の最後の 3 秒から減圧の終わりまで）の前面表示の濃度（RD）の中央値、2026-10-30 20:17 より前は減圧開始前 60 秒の中央値 | 個/cm³ |
| cpc_n | cpc_cm3 に使った 1 秒値の数（通常 13） | — |
| estimator | 使った推定器の名前 | — |
| flags | 異常の印（`|` 区切り、問題なければ空欄） | — |

> 列を追加・変更したプログラムで同じ日に保存すると、見出しの異なるファイルに追記しないよう、`cloud_data_YYYYMMDD_v2.csv` のように別のファイルに書きます。

flags の意味:

| 値 | 意味 |
|---|---|
| `nan_I0` | I0 が確定していない（起動から 10 秒未満） |
| `no_onset` | 減圧で気圧が下がらなかった |
| `no_cloud` | 雲が出なかった |
| `unstable_baseline` | 減圧が始まる前の Tr（20 パーセンタイル）が 0.995〜1.005 の外（2026-11-02 まで：雲が出る直前 1 秒の Tr で判定） |
| `sbi_no_onset`, `sbi_no_cloud`, `sbi_x_nan`, `sbi_timeout` | 推定器が推定しなかった理由：圧力の当てはめの失敗、雲の始まりが見つからない、x に NaN、事後分布のサンプリングが時間切れ（2026-11-02 から） |
| `no_laser` | I0 が 1 V 未満（レーザーが消えている、または光路がふさがれている）。推定はしない（qw、N は NaN） |
| `analysis_error`, `estimator_error` | 解析・推定で例外が起きた（`warnings_YYYYMMDD.log` を参照） |

### 9.4 CPC（TSI 3022A）のリアルタイム記録 `cpc\cpc_YYYYMMDD.csv`

CPC 背面の COM PORT（9 ピン、RS-232）を、USB-シリアル変換ケーブルでこの PC につなぎます。
設定は 9600 baud、偶数パリティ、7 データビット、1 ストップビットです（CPC の初期設定）。

**GUI で記録する（通常はこちら）**: GUI の「CPC ポート」にポート名（初期値 `COM3`、デバイスマネージャーで確認）を
入れておくと、運転開始と同時に CPC の記録も始まり、停止で止まります。

- 1 秒ごとの値を `cpc\cpc_YYYYMMDD.csv` に書きます（下の列）。
- 各サイクルの `cloud_data_*.csv` の行に、減圧の終わりまでの 1 サイクル（初期設定で 60 秒）の CPC の中央値
  `cpc_cm3` [/cm³] と、その中央値に使った 1 秒値の数 `cpc_n` を記録します。中央値にしているのは、異常値の影響を
  除くためです。
- **CPC は、雲チェンバーの試料配管とは別の短い管で、室内空気を直接吸わせてください**（2026-10-31 から）。
  チェンバーと同じ配管から分岐すると、V1 が開くたびに配管の圧力変化とフラスコからの逆流で CPC の値が数秒間
  大きく下がり（最大で約 9 割）、1 サイクルの中央値が低く出ます。CPC の入口は、チェンバーと露点計の入口の近くに置きます。
  2026-10-31 より前は同じ配管から分岐していたため、V1 閉の間（密閉の最後の 3 秒から減圧の終わりまで、13 秒）の
  中央値を記録していました。
- **露点計の下流に CPC をつながないでください。** 2026-10-31 11:46 までは CPC が露点計（流量 0.53 L/min）の下流に
  つながっていて、露点計の中で粒子が 2〜3 割失われていました。この期間の CPC の値は低く、雲チェンバーの N は
  CPC の約 1.3〜1.45 倍でした。CPC と露点計をそれぞれ独立に室内空気を吸わせた 2026-10-31 12:18 以降は、
  N と CPC がほぼ一致します。
  同じく 11:46 までは、露点計もバルブ系の近くで雲チェンバーと同じ配管につながっていて、バルブの開閉による
  圧力変化を受けていました（露点が低めに出て、qw の参照値が低くなる向き）。**2026-10-31 12:18 より前の露点計と
  CPC の値は、推定の検証には使わないでください。**CPC の流量は外部の流量計で 0.30 L/min（CPC の表示と一致）、
  CPC 3022A 2 台で同じ空気を測ると 5% 以内で一致することを確かめています。
- 1 秒値には、前面表示の濃度ではなく、カウント数 ÷ 流量（`counts_1s / flow_cm3s`）を使います。CPC は
  約 1 万個/cm³ を超えると、粒子を 1 個ずつ数える方式から散乱光の強さで濃度を求める方式（photometric）に切り替わり、
  前面表示の濃度がカウント数 ÷ 流量より約 2 割低くなるためです（2026-10-30 に確認）。1 個ずつ数える方式では、
  両者の差は 1% 程度です。流量の返答が読めない秒は、前面表示の濃度を使います。
  記録したファイルから同じ値を作るには `cloudchamber.cpc.read_logger_csv()`（初期設定でカウント数 ÷ 流量）を使います。
- CPC が止まっている、つながっていない、ポート欄が空欄のときは `cpc_cm3` を NaN、`cpc_n` を 0 として記録します。
  CPC が止まっている間は 10 秒ごとに再接続を試みます。運転状態の欄に「CPC [/cm³]」の最新値またはエラーを表示します。
- この列を加えたため、列の変わった日の `cloud_data_*.csv` は `_v2` などの別ファイルになります。

**GUI を使わずに CPC だけを記録する**: 別のウィンドウで次のように起動します。
GUI と同時には使えません（1 つのポートは 1 つのプログラムしか開けません）。

```
conda activate cloudchamber
python cpc_logger.py --port COM3 --test   # 各読み出しコマンドを 1 回ずつ表示して終了
python cpc_logger.py --port COM3          # 1 秒ごとに記録（Ctrl+C で停止）
```

- 列：`Time_stamp`、`datetime`、`conc_cm3`（前面表示の濃度、RD）、`counts_1s`（RB）、`flow_cm3s`（R4）、
  60 秒ごとに `ready`、`liquid_level`、各部の温度。
- 読み出しコマンド（R0〜RE）だけを使い、レーザー、ポンプ、ドレインなど CPC の状態を変えるコマンドは送りません。
- 2026-10-31 より前の記録では、CPC が雲チェンバーと同じ試料配管から吸引していたため、バルブの切り替えに同期して
  値が変わります（V1 が開いた直後の数秒間は大きく下がる）。その期間の 1 秒値から比べるときは、V1 閉の間
  （減圧開始の 3 秒前から減圧の終わりまで）のカウント数 ÷ 流量を使ってください。
  別の PC の Aerosol Instrument Manager で記録した 10 秒平均のデータ（2026-10-30 夕方まで）には、
  `cloudchamber.cpc.read_aim_csv()` と `smooth()`（60 秒の箱型平均と移動平均）または `median_before()` を使いますが、
  どちらも V1 が開いた間の低い値を含むので、配管が静止しているときの値より 1〜3 割低くなります。
- 同じ PC で記録するので、時計合わせ（10 章）は不要になります。
- この PC につなぐと、別の PC の Aerosol Instrument Manager では記録できなくなります。

## 10. 長期連続運転の注意

- **時計の同期**: 別の PC で記録した測定器のデータと比べる場合は、両方の PC の時計を NTP で合わせておく
  （GUI で記録する CPC は同じ PC の時計なので不要）。
- **バックアップ**: データフォルダを定期的に外付けドライブやサーバーへコピーする。
  OneDrive などの同期対象には入れない（小さなファイルが大量にできるため）。
- **Windows の自動更新・スリープ**: 運転中に PC が再起動・スリープしないよう設定しておく。

## 11. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 「デバイスを開けませんでした」 | デバイス名が違う（NI MAX で確認）、DAQ が抜けている、LabVIEW が同じ DAQ を使っている |
| 3 チャンネルが同じ電圧（約 1.4〜1.7 V） | 入力に何もつながっていない、センサーの電源が入っていない |
| 気圧や温度の値がおかしい | 配線のチャンネルの順番（ai0 = PD、ai1 = 気圧、ai2 = サーミスタ）、DAQ 機種の設定を確認 |
| バルブが動かない | DAQ 機種の設定（出力端子が機種で違う）、駆動回路の 24 V 電源、配線を確認 |
| 推定値が出ない（flags が `no_cloud`） | 空気が乾燥していて雲ができない、ポンプが動いていない、レーザーがずれている |
| Python が何も表示せずに終了する | 環境を有効化せずに実行している（2.1 節を参照） |
| CPC 欄に「エラー: cannot open COM3」 | USB-シリアル変換ケーブルが抜けている、ポート名が違う（デバイスマネージャーで確認）、`cpc_logger.py` など別のプログラムがポートを使っている |
| 運転中にエラーのダイアログが出た | プログラムはバルブを安全な状態に戻して停止しています。表示された内容を記録して担当者に連絡 |
